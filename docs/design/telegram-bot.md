# Telegram Bot 配置与使用

本文档面向站点运营者，覆盖 Telegram Bot 的完整配置流程和日常使用方式。

Bot 的能力分两侧：

| 侧 | 场所 | 能力 |
|---|---|---|
| 用户侧 | 与 Bot 的**私聊** | 绑定面板账号、接收订单/到期通知、联系人工客服 |
| 管理侧 | 一个开启话题（Topics）的**管理超级群** | 运营通知（每笔订单、每日流水日报）、客服会话话题、工单话题、全部管理员命令 |

管理侧的一切都发生在管理群里：**管理员命令在私聊中不可用**，订单通知和日报也只发到群内话题（群未配置或不可用时这些通知直接不发，不会回退私聊）。

---

## 一、前置准备

1. **创建 Bot**：在 Telegram 联系 [@BotFather](https://t.me/BotFather)，`/newbot` 创建，记下 Bot Token（形如 `123456789:AAxxxxxxxx`）。
2. **准备管理群**（可选，但管理侧功能全部依赖它）：
   - 新建一个群，进入群设置将其升级为**超级群**并开启 **Topics（话题）** 功能；
   - 把 Bot 拉进群，提升为**管理员**，权限中必须勾选 **Manage Topics（管理话题）**；
   - 获取群的 chat id（负数，形如 `-1001234567890`）。常用方法：
     - 把 [@getidsbot](https://t.me/getidsbot) 临时拉进群，它会回复群 id，随后可移除；
     - 或打开网页版 `web.telegram.org` 进入该群，地址栏 `#-100…` 即群 id。

## 二、配置项

配置存放在管理后台的 Telegram 认证方式设置中（`auth` 表 telegram 记录的 config JSON）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `bot_token` | string | BotFather 发的 Token。为空则整个 Bot 关闭 |
| `enable_notify` | bool | 通知总开关：订单通知、充值通知、日报、订阅到期提醒都受它控制 |
| `webhook_domain` | string | 公网 HTTPS 域名（如 `https://api.example.com`）。配置后走 webhook 模式；留空或 Debug 模式下走 long-polling |
| `group_chat_id` | string | 管理群 chat id（如 `-1001234567890`）。留空则所有群侧功能关闭 |

关于 webhook 无需其他配置：回调地址固定为 `{webhook_domain}/v1/telegram/webhook`，鉴权 secret 由系统从 Bot Token 派生并通过 `X-Telegram-Bot-Api-Secret-Token` 请求头自动校验，不需要也不应该手工设置。

## 三、配置步骤

1. 管理后台填入 `bot_token`（及需要的话 `webhook_domain`）、打开 `enable_notify`、填入 `group_chat_id`；
2. 在后台保存 Telegram 设置以触发 Bot 重新初始化（或重启服务）；
3. 查看服务日志确认：
   - `[Init Telegram Config] Webhook registered`（或 `Using long-polling`）—— Bot 已上线；
   - `[Init Telegram Config] Admin group ready` —— 群校验通过，Bot 会在群里自动创建「📣 运营通知」话题；
   - 若看到 `Admin group unusable, group features disabled`，按日志中的原因排查（见故障排查一节），修复后重新保存设置即可。

群校验要求三个条件同时满足：是**超级群**、开启了**话题**、Bot 是**具备管理话题权限的管理员**。任一不满足则群侧功能整体关闭（通知不发、命令不响应），修复后重新保存设置生效。

## 四、用户侧使用

### 绑定账号

两种方式，令牌均为 300 秒有效、一次性：

- **深链（推荐）**：面板「个人设置 → 绑定 Telegram」生成 `t.me/<bot>?start=<令牌>` 链接，用户点开后自动完成绑定；
- **手动**：私聊 Bot 发送 `/bind <令牌>`。

一个 Telegram 账号只能绑定一个面板账号，反之亦然；换绑需先在面板解绑。

### 私聊命令

| 命令 | 说明 |
|---|---|
| `/start <令牌>` | 深链绑定入口 |
| `/bind <令牌>` | 手动绑定 |
| `/help` | 查看可用命令与客服入口 |

### 联系客服

**已绑定用户**在私聊里直接发送任意消息（文字、图片等均可），Bot 会转发到管理群中该用户的专属话题；客服在话题里的回复会自动转回用户私聊。未绑定用户会收到绑定引导。

- 首次发起会话时用户会收到「已接入人工客服」的提示；
- 每个用户限 15 条/分钟，超出后当前窗口只提示一次；
- 客服关闭话题即结束会话（用户会收到通知），用户再次发消息会自动重新开启。

### 用户收到的通知（需 `enable_notify` 开启且已绑定）

购买成功、续费成功、流量重置、余额充值到账、订阅即将到期提醒、绑定/解绑确认。

## 五、管理群使用

### 三类话题

| 话题 | 来源 | 用法 |
|---|---|---|
| 📣 运营通知 | Bot 初始化时自动创建 | 每笔订单通知、每日流水日报（00:10 发前一天）。只读即可，勿在其中回复 |
| 💬 客服会话 | 用户私聊 Bot 时自动创建，标题为用户邮箱 + TG 用户名 | 直接在话题里回复即送达用户（**用户看不到是哪位客服回复的**）；关闭话题结束会话 |
| 🎫 工单 | 网站新建工单时自动创建，标题为工单号 + 标题 | 话题里发**纯文本**即作为管理员回复写入工单（网站同步可见）；关闭话题=关闭工单，网站关闭工单话题也会同步关闭；重新打开话题=重开工单 |

误删话题不用担心：下一条消息投递时 Bot 会自动重建话题并接续。

### 群内回复的权限

在客服/工单话题里发言会实际送达用户，因此发送者必须是**已绑定 Telegram 的面板管理员**。不满足条件时消息不会转发，Bot 会在话题里明确提示"回复未送达用户"——不会静默丢弃。匿名管理员身份（以群名义发言）无法通过校验，请用个人身份发言。

### 管理员命令（仅群内可用）

命令菜单只对群管理员显示；执行时按发送者身份鉴权（绑定关系 + 面板管理员角色）。回复会落在命令所在的话题里。

| 分类 | 命令 |
|---|---|
| 看板 | `/dash` 今日概览（待处理工单、收入、注册数） |
| 工单 | `/tickets [页码]`、`/tickets_waiting`、`/tk <ID>` 详情、`/rp <ID> <内容>` 回复、`/close <ID>`、`/reopen <ID>` |
| 用户 | `/user <邮箱\|ID>` 详情、`/user_sub <邮箱\|ID>` 订阅、`/user_log <邮箱\|ID>` 登录日志 |
| 运维 | `/reset <订阅ID>` 重置流量、`/toggle <订阅ID>` 启停订阅、`/ban <邮箱\|ID>` 封禁/解封 |
| 帮助 | `/help` 或 `/h` |

`/close`、`/reset`、`/toggle`、`/ban` 属危险操作，Bot 会要求在 5 分钟内用 `/confirm_xxx` 二次确认（`/cancel_xxx` 取消），且只有发起人本人的确认有效。

有了工单话题后，`/tk`、`/rp` 主要作为补充手段保留；日常处理工单直接在对应话题里回复更顺手，两者效果一致（都会写入工单记录）。

## 六、故障排查

| 现象 | 排查 |
|---|---|
| 日志出现 `Admin group unusable` | 按日志原因逐项核对：`not a supergroup with topics enabled`（群未升级超级群或未开话题）；`must be a group administrator with the manage-topics right`（Bot 非管理员或缺管理话题权限）；`get chat` 失败（chat id 填错，注意负号和 `-100` 前缀）。修复后重新保存设置 |
| 订单通知/日报没有发 | 依次确认：`enable_notify` 已开、`group_chat_id` 已配置且日志显示 `Admin group ready`。群不可用时通知**直接跳过**（日志中有 `Telegram admin notice skipped` / `report skipped` 及原因），不会积压重发 |
| 用户私聊无反应 | 确认用户已绑定（未绑定的非命令消息只会收到绑定引导）；确认 Bot 在线（`Telegram init success` 日志）；webhook 模式确认域名可从公网访问且证书有效 |
| 客服回复没送达用户 | 看话题内 Bot 提示：「未绑定管理员账号」「不是管理员」需补齐身份；「用户可能已停用 Bot」为用户侧屏蔽了 Bot |
| 改了配置不生效 | 配置读取发生在 Bot 初始化时，保存设置或重启服务以触发重载 |
| Bot 突然停止响应命令 | 检查是否有人撤销了 Bot 的群管理员权限；查看日志中的 `[Telegram Bot] update transport error` |

## 七、已知限制

- 上线前的**存量工单**不会创建话题，继续在网站或用 `/tk`、`/rp` 处理直至关闭；
- 工单话题创建失败（如创建瞬间 Telegram 不可达）后该工单不会再出现在群里，只能在网站处理（日志有 Error 记录）；
- 工单话题内只支持**纯文本**回复写入工单，图片等媒体会收到提示；
- 手动重命名话题不会同步回系统，话题被重建时会使用原标题；
- Telegram webhook 重投可能造成客服消息重复转发（无幂等去重）；
- 客服会话没有空闲自动关闭机制，需要客服手动关闭话题。
