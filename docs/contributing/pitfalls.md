# Pitfalls（中文）

## gomail 发不出去时不报错只挂着

`gopkg.in/gomail.v2` 的 `DialAndSend` **没有超时**。网络层不通的时候它不报错、
不重试，就一直挂在那里。

表现是这样的：任务入队成功、接口返回 200、前端正常走到倒计时，
审计表里那条记录的 `status` 永远停在「已尝试」，既不变成功也不变失败。
日志里一行错都没有。

```go
// 发送前先落一条 status=0 的记录，провider 调用返回后才改成 1 或 2
messageLog.Status = 0
_ = store.Log().Insert(ctx, audit)
err = sender.Send(...)   // ← 挂在这里，下面的代码永远不执行
```

**排查入口就是这个 status 卡在 0。** 它比日志可靠——日志里什么都没有，
而这条记录明确告诉你「调用发出去了，没回来」。

对照组：配置为空时反而会**立刻报错**，`dial tcp :0: connect: connection refused`
（host 空串、port 0，dial 本机 0 端口当场被拒）。所以「有报错」说明还没到网络层，
「没报错」才是真卡住了。

#### 顺带：`SMTPConfig.ssl` 这个字段压根没被读取

```go
type SMTPConfig struct {
    ...
    SSL  bool `json:"ssl"`   // ← 配置结构里有
}

func NewSMTPClient(conf *SMTPConfig) *SMTPClient {
    dailer := gomail.NewDialer(conf.Host, conf.Port, conf.User, conf.Pass)
    // conf.SSL 从头到尾没出现过
}
```

实际是否加密由 gomail 按端口号自己判断：**只有 465 走隐式 TLS**，其余端口
走 STARTTLS。所以填 `ssl: true` 但端口写 587，配置面板上看着是加密的，
实际走的是另一条路；把它当成开关去调试会白费时间。

## 迁移撞号后给 fork 那份改号，跑过旧版的库照样会跳过上游那条

fork 自己加了迁移 `03000_x`，后来上游也发了 `03000_y`。同步上游时把 fork 那份改成
`03024_x`，仓库里不再撞号，CI 全绿——**问题并没有解决**。

golang-migrate（以及大多数按版本号记账的迁移工具）只在库里存一个当前版本号。
跑过旧版的库记的是 3000，新代码一启动，它认为 3000 及以下都执行过了，于是上游的
`03000_y` **永远不会执行**，从 3001 往后接着跑。不报错，表就是缺一张。

真正暴露时是应用层报「列不存在」，离迁移很远，很难第一时间想到是这里。

#### 怎么发现

只看仓库发现不了。要拿一个**按旧版本迁移过的库**去跑新代码：
- 直接查目标环境：`select version, dirty from schema_migrations` + 上游那条迁移该建的表在不在
- 或在测试里复现：迁到撞号前一版 → 手工执行 fork 旧迁移的 SQL → `force` 到旧编号 → 跑 `Up`

#### 怎么修

改号之外，还要处理已经跑过旧编号的库。在迁移入口加一段识别：版本 **≥** 旧编号、不 dirty、
且上游那条迁移该建的东西不存在 → **直接执行上游那条的 up 脚本**，版本号不动。
判据里一定要有「上游那条的产物不存在」，否则正常跑过它的库也会被重跑。

别用「`force` 回撞号前一版再往上迁」：只对恰好停在旧编号的库有效。只要有一次不带修复的
部署，库就会越过旧编号继续往上迁（不报错），版本判据失效；退版本号又会让后面的迁移重跑。
先确认后面的迁移都不碰上游那条建的东西，补在它们之后执行才没区别。

fork 那份改号后会被再执行一次，所以它必须幂等。MySQL 8 的 `ADD COLUMN` 没有
`IF NOT EXISTS`（Postgres 和 MariaDB 有），要先查 `information_schema` 再 `PREPARE` 执行。

#### 以后怎么避免

fork 自己的迁移别用上游会用的编号段。上游用分段（LTS < 3000、feature ≥ 3000）时，
fork 应该挑一个上游不会碰的段，并在 `check-migration-lines` 一类的检查里锁住。

2026-10-18 又遇到：修复 PR 还没合，另一个会话先合了修 release 的 PR，不带修复的版本上了 test，
库从 3000 迁到 3024。最初「版本 == 3000 就退回」的修法当场失效，改成直接执行脚本。

只因为合并后发版恰好失败才没上线。
